# ЯРД — дизайн-прототип

Это **публичный тестовый сайт**, а не окончательная версия архитектурного бюро ЯРД.

## Как увидеть сайт
После включения GitHub Pages в **Settings → Pages** выберите:
- Source: **Deploy from a branch**
- Branch: **main**
- Folder: **/(root)**
- Save

Адрес после публикации: https://mirzyanova.github.io/yard-preview/

## Что сейчас работает
- Главная: описание бюро и слайдшоу избранных проектов
- Портфолио: разреженная адаптивная мозаика с подписями при наведении
- Страница каждого проекта: заголовок, стадия, год, перелистываемая галерея и описание
- Контакты; мобильная адаптация; свайп галереи
- Тестовая маршрутизация через `#/...`, совместимая с GitHub Pages

## Важно
**Все проекты и фотографии сейчас демонстрационные и не представляют реальные работы ЯРД.** Фотографии для предварительного просмотра загружаются с внешнего сервиса Unsplash; это временная уступка исключительно ради проверки визуального направления. До окончательного запуска они должны быть заменены материалами бюро и размещены на российском сервере. Шрифты также временные.

## Технический план
1. Утвердить внешний вид и поведение страниц на GitHub Pages.
2. Получить настоящие материалы проектов и лицензированные шрифты.
3. Внедрить систему управления контентом (CMS) и проверить добавление проектов без участия разработчика.
4. Разместить публичный сайт, CMS, изображения, шрифты и базу данных в России.
5. Протестировать, настроить резервное копирование, подключить действующий домен abyard.ru.

GitHub — **хранилище исходного кода** и история изменений. GitHub Pages — только временная площадка для просмотра. После переноса готовый сайт не должен загружать для посетителей рабочие ресурсы с GitHub или других иностранных серверов.

## Приватность тестового сайта

GitHub Pages в обычном публичном репозитории НЕ является приватной площадкой: ссылка доступна всем, кто её знает, а код и история изменений — в публичном репозитории. `noindex` лишь просит поисковые системы не индексировать сайт.

Для закрытого просмотра выбрана схема: приватный GitHub-репозиторий для исходников + тестовое размещение на российском HTTPS-хостинге с HTTP Basic Authentication (пароль до открытия страниц). Сначала отключить/снять с публикации GitHub Pages, затем перевести репозиторий в Private, потом настроить защищённый тестовый адрес. Пока защищённый адрес не готов, не публиковать конфиденциальные материалы бюро.

## Уведомление о cookie

В тестовом прототипе добавлена небольшая закрываемая плашка с информацией о cookie. Плашка показывается при каждом новом открытии сайта, а крестик закрывает её только до следующего обновления или открытия страницы. Данные о закрытии не сохраняются. Здесь нет аналитических и рекламных cookie. Перед окончательным запуском нужно проверить фактические cookie CMS и других сервисов и при необходимости реализовать согласие и политику обработки персональных данных.


## Публикация тестовой версии на Timeweb (без пароля)

**Сначала создайте рабочий аккаунт Timeweb** для виртуального хостинга (обычный тариф Year, не Timeweb Cloud). У аккаунта автоматически появляется технический домен вида `логин.tw1.ru`, связанный с основным сайтом. Для технического домена используется HTTPS.

1. Откройте https://timeweb.com/ru/services/hosting/ и оформите тест на виртуальный хостинг; выберите простой тариф.
2. Узнайте технический адрес в разделе «Домены и SSL» и проверьте, что он привязан к нужному сайту.
3. На GitHub скачайте текущую версию архива: https://github.com/mirzyanova/yard-preview/archive/refs/heads/main.zip
4. В панели Timeweb откройте «Файловый менеджер» → папку сайта `public_html`.
5. Загрузите архив и распакуйте его. В архиве GitHub файлы находятся во вложенной папке `yard-preview-main`; **перенесите содержимое этой папки, в первую очередь `index.html` и `.htaccess`, непосредственно в `public_html`**. Не оставляйте `index.html` внутри `yard-preview-main`. `README.md` и `.github` выкладывать в публичную папку не нужно.
6. Откройте свой `https://логин.tw1.ru/` с телефона и компьютера. Проверьте переходы по страницам, слайдшоу и галерею проекта. Убедитесь, что не осталось стартовой страницы хостинга.
7. Только **после подтверждения работы тестового адреса** отключите GitHub Pages в Settings → Pages и затем переведите репозиторий в Private (Settings → General → Danger Zone). GitHub Pages может отключиться при переводе в Private на бесплатном плане.
8. На следующих итерациях изменения в GitHub нужно будет отдельно передавать на Timeweb до настройки автоматического развёртывания через GitHub Actions и SFTP/FTP.

**Это публично доступный по прямой ссылке сайт, а не секретное или защищённое хранилище.** Гарантировать отсутствие в индексах нельзя, но мета-тег robots=noindex и HTTP-заголовок X-Robots-Tag в `.htaccess` сообщают поисковикам не индексировать его. Не размещайте конфиденциальные материалы без отдельного контроля доступа.

### Ограничения демонстрации
Весь проект текущей версии — один HTML-файл, а используемые фотографии пока загружаются с Unsplash. Для окончательного сайта шрифты и изображения необходимо переместить на российские серверы. Не включайте платный тариф и не меняйте настройки действующего домена `abyard.ru`, пока это не потребуется.

## Будущая административная панель и передача клиенту

**Текущая ссылка GitHub Pages — только тестовый дизайн.** Она не отвечает требованию размещения на российских серверах и не содержит админки для владельцев.

Для окончательной версии создаём самостоятельный сайт на российском хостинге в **аккаунте бюро**, с WordPress и собственной темой ЯРД. Владелец открывает /wp-admin и через раздел «Проекты»:
- создаёт карточку проекта;
- указывает название, стадию, год, локацию, описание;
- загружает обложку и фотографии галереи, меняет их порядок;
- включает или выключает проект на главной;
- публикует, снимает с публикации, исправляет или удаляет проект.

При создании/изменении проекта автоматически обновляются мозаика, список, индивидуальная страница и, при необходимости, слайдшоу.

Все реальные фотографии, сайт, база данных и шрифты должны храниться на российской инфраструктуре. Ни GitHub, ни сторонний зарубежный фотосервис не должны быть обязательны для работы опубликованного сайта.

До появления российского хостинга можно продолжать проверять визуал и наполнение в GitHub-прототипе. Перенос контента в WordPress проектируем как импорт, без повторной ручной загрузки тех же фотографий заказчиком.

## Доработки интерфейса от 6 ноября 2026

- Мозаика: при наведении затемнение всей фотографии и светлая подпись. На сенсорных устройствах подпись читается на нижней градиентной подложке.
- Список: превью соответствует геометрии карточки из мозаики (горизонтальная, вертикальная, квадратная).
- Будущие поля CMS: cardFormat (форма карточки), homeImage (отдельное главное фото), showOnHome (показ на главной), homeOrder (порядок), hasHorizontalHero (наличие горизонтального главного фото). Сейчас это данные JavaScript, не редактируемые в админке.
- Вертикальный «Клубный дом Форум» исключён из слайдшоу на главной. Подпись главной фотографии появляется при наведении на любую её область.
- Адаптивная сетка блока «ЯРД в цифрах» для телефонов. Навигационные стрелки и крестик cookie оформлены SVG, без символов, превращающихся в emoji на телефонах.
- На странице контактов добавлена форма: имя, email, сообщение и согласие. В текущем GitHub Pages нет серверной отправки: нажатие «Подготовить письмо» открывает приложение почты с заполненным письмом. Это НЕ автоматическая отправка.
- После переноса на Timeweb нужно реализовать серверную отправку на yard.bureau@mail.ru через настроенный SMTP/обработчик, защиту от спама, проверку доставки и полноценные документы об обработке персональных данных. Нельзя показывать статус «отправлено», пока сервер не подтвердил доставку.

Пока сайт остаётся тестовой GitHub-версией. Дизайн и данные проектов не переведены на Timeweb/WordPress.

## Композиция мозаики и размер карточек — 9 ноября 2026

Актуальный сайт на Timeweb: https://ch197840.tw1.ru/. Дизайн меняется в GitHub и публикуется через workflow; сами проекты и медиа остаются в WordPress.

В мозаике каждая карточка имеет три независимые характеристики:
- «Форма карточки» — горизонтальная, вертикальная или квадратная (существовавшее поле).
- «Визуальный приоритет / размер карточки» — новый выбор: «Автоматически — по композиции», «Маленькая», «Средняя», «Большая». Автоматический вариант чередует размеры для сбалансированного ритма. Размер не влияет на галерею и главное фото.
- «Порядок в портфолио» — уже существующее поле, отвечает за расположение карточек.

Новый параметр хранится в метаданных WordPress `_yard_card_size`, отдаётся через API как `cardSize`. Для ранее созданных проектов без значения действует `auto`. Новое поле появится в живой админке **только после отдельной установки обновлённого плагина** `cms/yard-projects/`. Автоматическая публикация дизайна по GitHub намеренно не затрагивает файлы WordPress.

Подпись под фото имеет компактный шрифт, участвует в вертикальном потоке карточки и не перекрывает следующую. Изображение чуть увеличивается при наведении. Мобильная раскладка сохраняет подписи видимыми.

## Страница проекта и масштаб фотографий (9 ноября 2026)

Референсы: [IND / Valtri](https://ind.studio/projects/valtri) — порядок материалов (визуализация, метаданные, описание, изображения), [XOPA / Old Ladoga](https://xopapraxis.com/81oldladoga) — визуальная подача основной фотографии без обрезки.

**Публичная страница:**
- Название уменьшено до типографически спокойного масштаба. Ссылка «Все проекты» остаётся сверху.
- Ниже — **одно основное фото проекта без обрезки**, в ширине между крайними осями страницы; вертикальные/квадратные изображения не растягиваются, по бокам остаётся белый фон.
- Под ним — заполненные параметры: **Локация / Год / Стадия**, пустые поля скрываются.
- Блок «О проекте» состоит из двух независимых полей WordPress: *Главная фраза* (крупнее) и *Описание проекта* (обычный текст).
- Ниже — **прокручиваемая галерея**, а не фиксированный по высоте слайдер. Каждая фотография без обрезки и с сохранением собственных пропорций. Для каждого кадра выбирается один из трёх размеров: **Большой** (по крайним осям страницы, 100%), **Средний** (76% на компьютере) и **Малый** (45% на компьютере). На телефоне масштаб адаптируется.
- Если основное фото совпадает с кадром галереи, этот кадр не повторяется второй раз.
- «Следующий проект» уменьшен примерно втрое и выровнен по правой оси.

**CMS WordPress, версия 1.0.4 (требует отдельного обновления установленного плагина):**
- Новое поле **«Общее фото проекта»**, отдельно от обложки мозаики и фотографии слайдшоу на главной. Если не заполнено, используется первый кадр галереи, затем обложка мозаики.
- В разделе **«Галерея проекта»** каждый загруженный кадр имеет собственный выбор размера (**Большой / Средний / Малый**). По умолчанию — большой. Порядок изображений меняется независимо от размера.
- Настройки сохраняются в безопасных метаданных `_yard_gallery_sizes` (JSON, индекс по ID изображения) и `_yard_page_image`. Старые проекты и их галереи сохраняются; незаданные значения имеют обратносуместимые настройки.
- Фотографии WordPress, их оригиналы, структура папки uploads и записи проектов не изменяются публикацией статики через GitHub.

До установки обновления плагина публичная страница уже может использовать собственные галереи из старого API (все кадры по умолчанию «Большие»). Установка плагина и активное значение версии на сервере — отдельная проверка. Не утверждать, что админка обновлена, пока это не подтверждено.

## Страница проекта — единая галерея + описание в двух колонках (9 ноября 2026)

Согласованная композиция основана на [XOPA Praxis / Old Ladoga](https://xopapraxis.com/81oldladoga) (одна галерея с миниатюрами и стрелками) и [Openfabric / M-TECH Alfredo Ferrari](https://www.openfabric.eu/projects/m-tech-alfredo-ferrari/) (информация о проекте отдельно от пояснительного текста).

- Все фото находятся **в одной галерее** перед описанием. Вместо разнесённых по странице кадров используются крупное активное изображение, боковые стрелки, нижняя полоса маленьких миниатюр и счётчик. Можно листать мышью, с клавиатуры и свайпами на телефоне.
- Изображение **не обрезается**: ограничения только по доступным ширине/высоте; вокруг кадра белое свободное пространство. Настройка `galleryItems[].size` управляет шириной активного кадра: **Большой 100%**, **Средний 76%**, **Малый 45%** на компьютере. Пропорции всегда оригинальные. Мобильные размеры адаптивны.
- Если `pageImage` заполнен, он открывает галерею первым. Дубликат из `galleryItems` исключается, остальные кадры идут в сохранённом редактором порядке.
- Далее единый двухколоночный блок: **слева** Локация / Год / Стадия построчно (только заполненные поля), **справа** главная фраза и описание проекта. На телефоне колонки располагаются друг под другом.
- Прежний большой заголовок и увеличенный «Следующий проект» не возвращать.
- Поля для размера каждого фото и отдельного `pageImage` подготовлены в плагине WordPress **1.0.4**, но до его фактического обновления на сервере фронтенд совместим со старым REST API: все фото отображаются в полном размере по умолчанию.
- Деплой статических файлов GitHub → Timeweb не перезаписывает WordPress, базу и `uploads`. Архив плагина `packages/yard-projects-1.0.4.zip` устанавливается отдельно.
