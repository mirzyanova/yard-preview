## Почему исходный FTP workflow заменён

Проверка AUTH TLS на vh474.timeweb.ru получила `530 Please login with USER and PASS`. Секреты не отправлялись. Передавать пароль до шифрования нельзя. Вместо FTP используется отдельная учётная запись WordPress yard-deployer с application password по HTTPS и единственной прикладной возможностью yard_deploy.

## Границы будущей установки

- public_html/index.php — постоянный минимальный загрузчик; server/root.htaccess задаёт DirectoryIndex index.php.
- public_html/yard-static/releases/<commit>/ — только проверенные файлы дизайна. current и previous переключаются атомарно. Выпуски сохраняются; удаления CMS/медиа в механизме публикации нет.
- public_html/cms — WordPress; база выделенная; wp-content/uploads — российская медиабиблиотека. Эти пути не принимаются API публикации.
- server/static.htaccess защищает служебные указатели и запрещает выполнение PHP внутри статических выпусков. server/uploads.htaccess запрещает исполняемые файлы в медиабиблиотеке.
- Секреты базы, ключи WordPress и при необходимости SMTP — только в защищённой серверной конфигурации. GitHub: секреты окружения timeweb-preview YARD_DEPLOY_USER и YARD_DEPLOY_APP_PASSWORD.
- TIMEWEB_DEPLOY_ENABLED по умолчанию отсутствует/false. Включать только после установки, проверки API, пробной публикации и отката.
- Для первичной серверной установки нужен временный SSH и создание БД/учётных записей; перед расширением доступа требуется подтверждение пользователя. Секреты не запрашивать в чате и не выводить в инструменты.
- Не пользоваться автоматическим установщиком Timeweb 6.7.1: он предлагает отдельный сайт/домен и устаревшую версию. Не нажимать «Начать установку» в этом мастере.
